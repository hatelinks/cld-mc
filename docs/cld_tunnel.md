# cld_tunnel: Игра по сети

Карта кода. Читать вместо разбора исходников; кто меняет мод, обновляет эту страницу в своём PR.

- modId `cld_tunnel`, папка `tunnel/`, мод **0.1.0** (`VERSION` в `tunnel/build.sh`), relay **0.1.1** (`tunnel/build_relay.sh`). Только клиент (`dist = CLIENT`), на сервер не ставить.
- Свой аналог e4mc: одиночный мир после «Открыть для сети» получает адрес на нашем relay-сервере, друзья заходят по нему обычным клиентом сборки, без проброса портов. Код e4mc не использовался, протокол свой.
- Две части: мод (`cld_tunnel-neoforge-1.21.1-<версия>.jar`) и relay (`cld_tunnel-relay-<версия>.jar`, чистая Java 21 без библиотек, ставится на VPS).
- Пререлизы: `releases/cld_tunnel-0.1.0/` (jar мода и zip с relay), `releases/cld_tunnel_relay-0.1.1/` (relay и скрипт установки с открытием портов в iptables для Oracle Cloud).
- Решения владельца (анкета 02.11): relay на бесплатном облаке (Oracle Free Tier), без домена (адреса вида IP:порт), свой TCP, без совместимости с e4mc, открытие мира только по ключу, постоянный адрес мира.

## Как работает
1. Мод раз в секунду смотрит, открыт ли одиночный мир для сети (`IntegratedServer.isPublished`, без миксинов). Если да и в настройках есть relay, открывает управляющее TCP-соединение к relay (порт 25580).
2. Relay шлёт `CLDT 1 <nonce>`, мод отвечает `AUTH <HMAC-SHA256(ключ, nonce)> <id мира>`. Сам ключ по сети не ходит.
3. Relay отвечает `OK <адреса>`: по имени `tihiy-les-42.<domain>` (общий порт 25565, мир выбирается по адресу из пакета handshake Minecraft) и/или по порту `<address>:<порт мира>` (диапазон `ports`). Мод пишет адреса в чат, по клику копируются.
4. Игрок заходит на relay. На каждого игрока relay шлёт хосту `OPEN <id>`, мод соединяется с локальным сервером мира (127.0.0.1:порт LAN) и открывает к relay второе соединение `DATA <id>`; дальше байты идут как есть. Если локальный сервер не ответил, мод шлёт `FAIL <id>`, игрок сразу получает отказ.
5. `PING`/`PONG` каждые 20 с, молчание 60 с считается обрывом. Мод переподключается сам (2, 4, 8... до 60 с), адрес прежний. Игроки, которые уже в мире, при обрыве управляющего соединения не вылетают.
6. Если мира с таким именем нет, relay сам отвечает: в списке серверов текст «Мир ... сейчас не открыт», при входе экран отказа.

Адрес постоянный: id мира лежит в `<папка мира>/cld_tunnel.txt`, имя и порт выводятся из хэша id и запоминаются relay в `relay-state.txt` (там только хэши id). Копия мира в другой папке получает новый id и свой адрес, чтобы две копии не выбивали друг друга. Если тот же мир подключился второй раз, relay отдаёт адрес новому, а старому шлёт `ERR FATAL`.

## Файлы
| Файл | За что отвечает |
|---|---|
| `core/Proto` | Константы протокола, чтение строк побайтно (чтобы не съесть данные игрока), HMAC, случайные id. |
| `core/Pipe` | Перекачка байтов между двумя сокетами в обе стороны, полузакрытие передаётся дальше. |
| `core/TunnelClient` | Сторона хоста без Minecraft: управление, переподключение, `OPEN`/`DATA`/`FAIL`. Его же используют тесты. |
| `TunnelMod` | Класс мода: настройки, экран настроек NeoForge, тик, команда `/cldtunnel` (`start`, `stop`, без аргумента адрес и число игроков). |
| `HostTunnel` | Связка с игрой: включает туннель при открытии для сети, сообщения в чат, id мира, `offlinePlayers`. |
| `TunnelConfig` | `config/cld_tunnel-client.toml`. |
| `relay/Relay` | Сам relay: хосты, имена, порты миров, ожидание `DATA` (10 с), лимиты, файл состояния. |
| `relay/McWire` | Разбор handshake Minecraft, ответы «мир не открыт» для пинга и входа. Старый пинг 0xFE просто закрывается. |
| `relay/Names` | Слова для имён миров. |
| `relay/RelayConfig`, `relay/RelayMain` | `relay.properties`, запуск, пример настроек с новым ключом. |

## Настройки мода
`auto` (открывать вместе с LAN, да), `relay` (адрес relay, можно с портом), `key` (ключ relay), `offlinePlayers` (пускать без лицензии, нет: иначе можно зайти под любым ником). В игре: TC Моды, раздел «Игра по сети», «Открыть настройки мода».

## Relay
```sh
tunnel/build_relay.sh                               # tunnel/dist/cld_tunnel-relay-0.1.0.jar
sh install_relay.sh cld_tunnel-relay-0.1.0.jar mc.example.ru 81.2.3.4   # на VPS от root
```
`relay.properties`: `control` (порт для модов), `public` (общий порт игроков), `domain` (для адресов по имени, нужна DNS запись `*.domain` на сервер), `address` и `ports` (адреса по порту без домена), `key`, `maxHosts`, `maxPlayersPerHost`, `state`. Открыть в файрволе 25580, 25565 и диапазон `ports`. Памяти хватает 256 МБ.

Oracle Cloud Free Tier (выбор владельца): образ Ubuntu 24.04 (ARM Ampere или AMD, оба подходят), без домена:
```sh
sh install_relay.sh cld_tunnel-relay-0.1.1.jar "" <публичный IP>
```
Скрипт сам открывает порты в iptables (в образах Oracle там REJECT, ufw нет). Отдельно в консоли Oracle: VCN, Security List, Ingress Rules, TCP 25580 и 25601-25650 с 0.0.0.0/0. В моде: relay `<IP>:25580`, ключ из вывода скрипта.

## Сборка и тесты
```sh
LIBS=/mnt/project-files/libs tunnel/build.sh   # мод
tunnel/test.sh                                 # 22 проверки relay и туннеля без Minecraft
```
`tunnel/test/RealServerTest.java`: проверка с настоящим сервером NeoForge 21.1.248 (offline): relay из jar, хост `TunnelClient`, пинг списка серверов и вход до фазы настройки по имени и по порту. Сервер ставится как в `qa/server.sh`. 02.11 прошла полностью.

## Грабли
- Игроки через relay видны серверу мира как 127.0.0.1: баны по IP не работают.
- Без `offlinePlayers` друзьям нужна лицензия, как с обычным LAN.
- Минимальный протокол: при смене формата строк поднимать `Proto.VERSION`, старый мод получит понятную ошибку.
