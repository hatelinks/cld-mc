# Отдел тестирования (qa/)

Всё, что делают отделы датапаков, модов и UI, проходит здесь до передачи игроку.

## Инструменты

| Скрипт | Что делает | Нужна сеть |
|---|---|---|
| `python3 -I qa/check_mods.py <mods> [--datapacks …] [--android] [--server]` | Статическая проверка набора: дубликаты modId, обязательные зависимости и версии (точный порт Maven/FML, включая правило FML 4 «1.21 засчитывается как 1.21.1»), несовместимости, jarjar, mixin-конфиги и их классы, датапаки (pack.mcmeta, pack_format 48, JSON, имена папок 1.21), нативные библиотеки, риски для Android, клиентские моды на сервере | нет |
| `python3 -I qa/tests/selftest.py` | Проверка самой проверки: заведомо сломанные моды/датапаки должны ловиться | нет |
| `qa/server.sh <mods> [датапаки…]` | Смоук-тест выделенного сервера NeoForge 21.1.248: установка, запуск без клиентских модов, `datapack list`, `reload`, прогрузка 160×160 блоков, `stop`, отчёт по логу | maven.neoforged.net, libraries.minecraft.net, piston-*.mojang.com |
| `python3 -I qa/log_report.py <latest.log> [crash-reports]` | Разбор лога: время запуска, ошибки по источникам, mixin/датапак/теги/конфиги/реестры/сеть, краши; известный безвредный шум (IDAS, CSA) отделяется | нет |

Сборка из Releases (`cld-mc-pack.zip`) скачивается через GitHub API (assets/<id>, `Accept: application/octet-stream`).

## Порядок приёмки

1. **Датапаки.** `check_mods.py <mods> --datapacks <zip>` без ошибок; после серверного теста в логе нет `datapack`/`tags` ошибок с id этого датапака; `/datapack list` показывает его включённым.
2. **Моды.** jar собирается из исходников репозитория (`<мод>/build.sh`), версия в имени файла = версия в mods.toml; `check_mods.py` с новым jar без новых ошибок; серверный смоук-тест (если мод не только клиентский) — «Done» без mixin-ошибок и крашей.
3. **UI.** Клиентский мод не ломает сервер (нет в серверном наборе или грузится на нём без падения); проверка классов клиента на сервере (`net/minecraft/client` в общем коде) — по коду; скриншоты/превью — от отдела UI.
4. **Android.** `check_mods.py --android`: Sable только вместе с sable-android-support, без Sodium/Iris, нативные библиотеки с arm64-сборкой; живой запуск — только на телефоне игрока.
5. **Итог** — короткий отчёт: что проверено, чем, результат, что осталось проверить в игре.

## Чего нельзя проверить в облаке

Клиент с рендером (Sodium, Veil, DH, шейдеры, экраны модов) и Android-лаунчер — только у игрока. Для них отдел готовит чек-лист «что посмотреть в игре» и разбирает присланные логи через `log_report.py`.
